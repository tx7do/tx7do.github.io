# GoWind Admin｜风行 — 开箱即用的企业级全栈中后台框架：Excel 导入导出

> "这个列表能导出 Excel 吗？""能不能批量导入？"——做管理系统交付的两个必问题。很多开源脚手架的答案是"请自行实现"，于是一个导出按钮在几十个列表页被复制粘贴几十遍，格式五花八门。风行（GoWind Admin）把导入导出做成了**统一的封装 + 全面的铺面**：管理页批量挂上导入导出能力，体验一致、代码零重复。

## 一、导出：一个按钮组件铺满全站

列表页工具栏的「导出」按钮来自统一的 `TableExportButton` 封装：当前搜索条件、当前列结构一键导出为 `.xlsx`，文件即点即得。这个封装已经铺满了三端的主要列表页：

- **React 端 30 页**：组织人员（用户/职位/组织架构）、权限管理、日志审计（API/操作/数据/权限/登录五类日志）、通知渠道、站内信、租户管理……
- **Vue Element 端 25 页、Vue Vben 端 30 页**同构覆盖。

![](/assets/images/gowind-admin/users-export.png)

对采用者的意义：你新建的业务列表页，从模板起步就带着导出能力，不需要"导出"再排一次期。

## 二、导入：模板下载 + 拖拽上传 + 格式校验

导入走的是同一个交互范式：「导入数据」弹窗 → 下载导入模板（按当前资源的列结构生成）→ 拖拽或点选上传 `.xlsx` → 后端解析校验入库。

![](/assets/images/gowind-admin/import-modal.png)

两个细节值得说：

- **模板是活的**：导入模板跟着字段定义走，字段加了模板跟着变，不会出现"文档里的模板和系统对不上"的交付事故；
- **只收 xlsx**：拒绝 csv/xls 糊弄事，编码、注入、多 sheet 歧义在入口就挡掉。

## 三、技术形态的诚实交代

风行的导入导出目前是**前端生成**路线（浏览器端 exceljs 直接产出 xlsx），这带来两个天然优势：服务端零负载（不占后端内存与带宽）、实现一致（三端同一套封装）；代价是超大导出（十万行级）受浏览器内存约束——这类需求本就该走异步任务 + 服务端流式生成，风行把它留给有此规模的采用者按需接入，而不是让所有页面为极端场景买单。

导入侧的解析与校验在服务端，数据质量把关不依赖前端。

## 结语

导入导出没有技术难度，只有工程纪律：统一封装、全面铺面、模板跟随字段。这三件事做到位，"能不能导出"就再也不出现在客户验收清单上。
