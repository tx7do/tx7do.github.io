# GoWind Admin｜风行 — 开箱即用的企业级全栈中后台框架：套餐与计费管控

> 把一套管理系统卖给多家客户（SaaS 化），光有租户隔离还不够——你得回答这三个商业问题：**免费版能用哪些功能？套餐到期了怎么办？用量怎么计量？**多数项目在接第一单时才想起这些，然后用手写 SQL 改库、人工停账号的方式勉强运转。风行（GoWind Admin）把套餐体系做成了平台原生的三层结构：套餐目录、模块白名单、配额计量，配合三档到期处置策略全自动执行。本文拆解这套 SaaS 化运营能力。

## 一、三层模型：目录、白名单、配额

```
配置面    sys_plans（套餐目录：版本 / 到期策略 / 描述）
          sys_plan_modules（套餐 → 功能模块白名单）
          sys_plan_quotas（套餐 → 配额）
                      │ 管理页维护（租户管理 → 套餐管理 / 配额管理）
                      ▼
绑定面    sys_tenants.plan（套餐外键）+ expired_at（到期时间）
                      ▼
执行面    模块白名单 → HTTP 租户闸门（fail-closed）
          到期处置   → 三档策略全自动执行
```

![](/assets/images/gowind-admin/plans.png)

管理页左侧是套餐目录（图中三档：免费版 / 标准版 / 企业版），右侧是每个套餐的配额面板——用户上限、存储空间、API 调用量、AI Token，随套餐维护。

## 二、模块白名单：商业开关长在闸门上

每个套餐维护一张**功能模块白名单**（仪表盘 / 组织人员 / 系统管理 / 字典 / 租户 / 权限 / 日志审计 / 站内信 / 文件 / 任务 / AI……）。执行点是 HTTP 层的租户闸门：每个租户请求按（路由模板，method）查 Api 表归类到模块，再对照租户套餐的白名单——**不在白名单里的模块，整个端点 fail-closed 403**。

这就是"给付费版开通 AI 模块、免费版不给"的实现方式：不是在前端藏菜单（那只是体验优化），而是在后端闸门上拒绝。给某个套餐开通/关闭一个模块，是套餐管理页里加/删一行白名单的操作，即时生效。

## 三、到期处置：三档策略全自动

套餐定义**到期处置策略**（`expiry_policy`），租户到期后自动进入对应档位：

| 策略 | 语义 | 生效时延 |
|---|---|---|
| **READONLY**（默认） | 即时只读降级：仅 GET/HEAD/OPTIONS 放行，其余 403 | 即时（闸门逐请求判定） |
| **BLOCK_LOGIN** | 租户状态置 EXPIRED，拒绝登录 | 最迟 1 小时（扫描周期） |
| **FREEZE** | 租户状态置 FREEZE，冻结 | 最迟 1 小时（扫描周期） |

后两档由系统级周期任务（每小时整点）扫描执行：圈定已到期租户 → 按策略改写状态 → **吊销该租户全部用户的全部端令牌**（即时踢下线）→ 后续由登录与闸门的"非 ON 即拒"路径接管。

续费恢复也是明确的运维路径：READONLY 档改回到期时间即时恢复；BLOCK_LOGIN / FREEZE 档续费后把租户状态置回 ON 并延后到期时间。三档语义、生效时延、恢复流程全部写在文档里，没有"到期了行为是什么"的猜谜。

## 四、配额与用量计量

三类经典配额（用户上限 / 存储空间 / API 调用量）+ AI Token 月度配额，按套餐维护；用量计量端点 `GET /admin/v1/tenants/{id}/usage` 一次返回套餐上限与当前用量的对照：

- **用户数**：按租户 COUNT 用户表；
- **存储用量**：按租户 SUM 文件大小；
- **API 调用**：按租户 COUNT API 审计日志（用量计量直接复用审计数据，不需要另埋计数器）；
- **AI Token**：每次模型调用（对话 / embedding / 问数）写入用量流水，月度聚合对照配额，**超限硬拒绝**——这是唯一做了硬执行的配额维度，也是最容易失控的成本项。

一个设计取向值得说明：用户/存储/API 三类配额当前定位是**计量展示**（租户详情页的用量/配额对照），未做超限硬拦截——先把计量做准，硬限制按业务节奏接入。AI Token 因为对应真金白银的模型调用成本，从第一天就是硬限制。

## 五、租户数据清理：合规退出机制

租户注销/退租时的数据清理是 SaaS 的合规刚需。`POST /admin/v1/tenants/{id}/cleanup` 在**单事务内硬删**该租户在全部带租户维度的业务表中的数据，保留租户行（状态置 OFF）并吊销全部用户令牌——不可逆操作，执行前走备份快照，全程受租户闸门与权限面管控。

## 六、管理面速览

- **套餐管理**：套餐 CRUD（名称唯一），版本/到期策略维护，级联管理白名单与配额；
- **配额管理**：按套餐维护四类配额值；
- **租户管理**：租户创建（`CreateTenantWithAdminUser` 一步完成"建租户 + 建租户管理员"）、套餐绑定、到期时间维护、到期状态展示。

![](/assets/images/gowind-admin/tenants.png)

排障口诀写在文档里：**租户突然全 403 或无法登录** → 查租户状态（EXPIRED/FREEZE 即到期扫描所置）→ 查套餐到期时间与处置策略 → 查模块白名单 → 查接口同步。一条决策树走到底。

## 结语

SaaS 化不是"加个 tenant_id 字段"——从租户隔离、模块白名单、配额计量到到期处置，是一条完整的产品化链路。风行把这条链路做成了平台原生能力，管理页点点即可运营，让你接第一单 SaaS 客户的那天，工程上已经就绪。
