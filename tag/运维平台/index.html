GoWind Ops 拆解：不引入分布式锁的多副本协调
Date: 10/22/2026Category: GoWind风行Tag: Golang, Go-Kratos, GoWind, 分布式, 运维平台

本文回答一个问题：core 服务水平扩到多副本之后，定时任务、指令回执、构建触发、告警外呼，靠什么保证不重复执行——而又不引入 Redlock、etcd concurrency、ZooKeeper 分布式锁里的任何一种？

GoWind Ops 的 core 是唯一连库的领域服务，天然想水平扩：多副本分摊 MQTT 信令、多副本跑定时调度。但多副本立刻带来一组经典问题——同一分钟的双 cron 触发、同一指令的重复回执、同一配置的并发构建。常见的答案是上一把分布式锁，GoWind Ops 的选择是把协调拆散进它已经在用的三个层：MQTT broker 的投递语义、数据库条件更新、Redis 原子操作。全仓找不到 redsync / etcd concurrency / 抢占式锁服务里的任何一种"锁服务"。

GoWind Ops 深度拆解：纯出站 Agent + MQTT 信令，把「管机器、跑项目、发脚本、构建分发」做扎实
Date: 10/22/2026Category: GoWind风行Tag: Golang, Go-Kratos, GoWind, MQTT, 运维平台

本文回答一个问题：当你点下「分发到 20 台机器」，从浏览器到目标机磁盘落定，中间经过了哪些服务、哪些协议、哪些状态机与哪些防呆设计？

GoWind Ops 是一个多节点运维平台，Go 后端（Kratos 微服务 + Ent + PostgreSQL/Redis/MinIO）+ React 19 管理台。它不做大而全的 K8s 替代品，聚焦四件事：管机器、跑项目、发脚本、构建分发，组织权限、审计日志、数据字典作为系统底座内置。
